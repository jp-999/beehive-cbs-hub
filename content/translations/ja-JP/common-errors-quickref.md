### 見落としやすい V6 のルール

- **Critical failure** — ユーザーが行動の根拠にするもの（数値、手数料、日付、法的規則、引用、連絡先、送信する文面）の中で、留保なく事実として述べられた誤り。**Issue #1** に置き、**モデルを 3 に制限**します。
- **Language & locale fit** は Issues に含めます — Country fit は 2 または 3 とし、問題を Bad comment に記載します。
- **Rubric のガードレール** — 列挙された例外が当てはまり justification で説明される場合を除き、rubric の Yes が少ないモデルを多いモデルより上に置かないこと。
- **`[FLAG]` は評価を変えません。** どのモデルも満たせない基準（例：コネクターなしの「uses KakaoTalk」）は **No + `[FLAG: Impossible to satisfy]`** のままにします。

### 「初見の人として読み返す」チェック

提出する前に、共有リンクしか持っていない人になったつもりで各項目を読み返してください:

1. すべての issue が、引用した turn で共有ページ上に見えますか？
2. すべての Detail 行が、モデルが実際に言ったことをその言葉で引用していますか？
3. すべての rubric の justification が、最終状態を示す turn を挙げていますか？
4. ranking の justification は、rank フィールドと同じ最良・中間・最低を挙げていますか？
5. モデルが作成したすべてのファイルが、リンクまたは zip で見えますか？

### 重大な不正（ハードフェイル）

これらはタスク**と**コントリビューターの両方にフラグが付きます:

- 別の会話・アカウント・タスクの JSON やスクリーンショット。
- redo を求められた後、同じ会話を変更せずに再提出すること。
- ステップを省くために以前のチャットを新しいチャットに貼り付けること。
- モデルが作成していないファイルをアップロードすること。
- アップロードに個人的な文書が含まれること。

### 覚えておくべき 3 つのこと

1. **ユーザーの訂正は常に issue です。** それが起きた turn で記載してください。
2. **ランキングは自分の score と rubric に従わなければなりません。** 例外は必ず文章で説明してください。
3. **評価するものはすべて監査者に見えなければなりません** — 共有リンク、JSON、または zip。
